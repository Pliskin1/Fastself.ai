# Edge functions and client API

All functions live in `supabase/functions/<name>/index.ts` (Deno). Shared code is in `supabase/functions/_shared/`:
- `core.js` is generated by `pnpm build:edge` from `packages/core/src/edge.ts`. Never edit it by hand. CI fails if it is stale.
- `cors.ts`, `json.ts` (respond helpers), `ai.ts` (provider interface), `limits.ts` (rate limit), `supabaseAdmin.ts`
  (service-role client, never exported to the app).

Secrets (set with `supabase secrets set`, local in `supabase/.env.local`):
- `AI_PROVIDER` = `anthropic` (default) | `cloudflare`, and `ANTHROPIC_API_KEY`.
  Optional for Cloudflare: `CF_ACCOUNT_ID` and `CF_API_TOKEN`.
- Sign in with Apple: `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` (the .p8 content), `APPLE_CLIENT_ID` = `ai.fastself.app`.
- `HASH_SALT` for device hashes.

The app calls functions only through `apps/mobile/src/lib/api.ts` (`supabase.functions.invoke`), with the anon key or the
user JWT.

**Keys and JWT checks.** The app uses the project's legacy `anon` key (a JWT; Project Settings → API Keys → Legacy).
If a project offers only the new `sb_publishable_...` key, the default `verify_jwt` gateway check rejects it: then set
`verify_jwt = false` for `meal-suggest` and `meal-plan` in `supabase/config.toml`, keep the rate limit, and in
`apple-token` and `delete-account` always verify the caller with `supabaseAdmin.auth.getUser(<bearer token>)`. Do the
`getUser` check in those two functions in every case; it costs nothing and does not depend on the gateway.

## 1. POST `meal-suggest`
Guests and users can call it (verify_jwt true: the anon key is accepted). The app calls it only after AI consent.

Request (zod, rejects unknown keys):
```ts
{ forbidden: Category[] (max 30), avoid: string[] (max 10, each ≤ 30 chars, letters/spaces only),
  meal: 'dorucak'|'rucak'|'vecera'|'sehur'|'iftar', ingredients: string[] (max 12, each ≤ 30),
  locale: 'sr-Latn', device: string (uuid; hashed server-side), rulePackVersion: string }
```
Server steps:
1. Validate; return 400 with `{ error: 'invalid_input' }` on failure.
2. Rate limit: `private.ai_usage` keyed by `sha256(device + HASH_SALT)` and the day allows 20 a day; an IP bucket in memory
   allows 60 a day. Exceeding either returns 429 `{ error: 'rate_limited' }`.
3. Call the provider (§5) for 3 recipes, with a timeout of 12 s.
4. Map each recipe's ingredients to categories (core `categorize`) and run `validateRecipe` against `forbidden` + `avoid`.
   Drop failures and return their reasons in `rejected` (max 2).
5. If fewer than 1 recipe passes, retry once with the reasons appended to the prompt. If it still fails, return
   `fallback: true` with up to 3 built-in recipes from core that pass.
Response 200:
```ts
{ recipes: Recipe[], rejected: { title: string, reason: string }[], fallback: boolean, provider: 'anthropic'|'cloudflare' }
```
Logs hold no payload content, only counts and latency.

## 2. POST `meal-plan` (P1)
Request: `{ days: { date, forbidden: Category[], meals: ('rucak'|'vecera'|'iftar'|'sehur')[] }[] (max 7), avoid, locale, device }`.
The server builds a 7×2 plan, preferring built-in recipes and asking the AI for at most 4 new ones, then validates every
item per day. Response: `{ days: { date, items: { meal, recipe }[] }[] }`. It counts as 3 against the rate limit.

## 3. POST `apple-token` (authenticated)
Body: `{ authorizationCode: string }`.
1. Build the client secret JWT (ES256, the .p8 key, iss = team id, sub = client id, aud https://appleid.apple.com, exp 5 min).
2. POST https://appleid.apple.com/auth/token (grant_type=authorization_code) and read the `refresh_token`.
3. Upsert `private.apple_tokens(user_id, refresh_token)`.
4. Return `{ ok: true }`. Failure is non-fatal for sign-in (the app logs it and continues).

The client flow (`src/lib/auth.ts`):
```ts
const rawNonce = randomUUID(); const hashed = await Crypto.digestStringAsync(SHA256, rawNonce);
const cred = await AppleAuthentication.signInAsync({ requestedScopes: [EMAIL], nonce: hashed });
await supabase.auth.signInWithIdToken({ provider: 'apple', token: cred.identityToken!, nonce: rawNonce });
if (cred.authorizationCode) api.appleToken(cred.authorizationCode);   // fire and forget
```
Email OTP: `supabase.auth.signInWithOtp({ email, options: { shouldCreateUser: true } })`, then
`verifyOtp({ email, token, type: 'email' })`. In Supabase Auth settings, set the OTP length to 6 and expiry to 600 s,
and use the email template with `{{ .Token }}`. Session storage is `expo-sqlite/localStorage` (see the Supabase Expo docs).

**Custom SMTP is required in prod.** Supabase's built-in mailer only delivers to the project team's addresses and is
heavily rate limited, so App Review's email login would fail. In fastself-prod: Authentication → Emails → SMTP settings.
Use Resend (free tier, needs a domain you control with SPF/DKIM records) or Brevo (free tier; a verified sender
address works without a domain, but mail is more likely to land in spam). Sender name "fastself.ai". Set the
Auth rate limit for emails to at least 30/hour. Test with a Gmail and an iCloud address before submitting.

## 4. POST `delete-account` (authenticated)
1. Read the user from the JWT.
2. If `private.apple_tokens` has a row: POST https://appleid.apple.com/auth/revoke with `token=refresh_token`,
   `token_type_hint=refresh_token` and the client secret. Log the status.
3. `auth.admin.deleteUser(user.id)`. Profiles cascade to all user tables; reports set user_id null; private.apple_tokens
   cascades.
4. Return `{ ok: true }`.

The app then signs out, clears the outbox and consents, and offers "Obriši i podatke sa telefona" (default yes).
**Test:** pgTAP checks the cascade; a Deno test with a mocked fetch checks revoke is called; E2E on the dev project deletes a real user.

## 5. AI provider interface (`_shared/ai.ts`)
```ts
interface AiProvider { suggest(input: SuggestInput, extraNote?: string): Promise<RawRecipe[]> }
```
**Anthropic** (default): POST https://api.anthropic.com/v1/messages with the headers `x-api-key`,
`anthropic-version: 2023-06-01`, `content-type: application/json`.
- Body: `model: 'claude-haiku-5-5'`, `max_tokens: 1500`, `temperature: 0.7`, and the system prompt below.
- Forced tool use: one tool `return_recipes`, whose input_schema is the JSON schema of RawRecipe[] (3 items), with
  `tool_choice: { type: 'tool', name: 'return_recipes' }`.
- Read `content[].type === 'tool_use'` → input.

System prompt (keep short; it is a cost driver):
```
Ti si kuvar iz Crne Gore. Predloži 3 jednostavna domaća recepta na crnogorskom (ijekavica, latinica).
Strogo zabranjeno u sastojcima i koracima: {forbidden_human}. Izbjegavaj i: {avoid}.
Obrok: {meal}. Koristi koliko možeš: {ingredients}. Bez mesnih zamjena koje kriju zabranjene sastojke.
Kod posta na vodi ne koristi ulje ni u jednom koraku. Svaki recept 3–5 koraka, vrijeme u minutama.
Ne daj zdravstvene savjete.
```
RawRecipe: `{ title, timeMin, ingredients: { name, category }[], steps: string[] }`. The category enum is from core.

**Cloudflare** (fallback option): Workers AI REST `@cf/meta/llama-3.1-8b-instruct` (or newer) with JSON mode. The same
interface applies; validation catches quality issues.

To change providers, change the secret `AI_PROVIDER` and the provider name in COPY `ai.consent.provider` and in the
privacy policy, then ship a new build (the consent text names the provider).

## 6. Reports (no function)
The app inserts into `public.reports` via PostgREST with the anon key or the user JWT:
`{ type, day, context, message, rule_pack_version, app_version }`. RLS allows insert only.

## 7. GET `health`
Returns `{ ok: true, time }`. It is public: `supabase/config.toml` has `[functions.health]` with `verify_jwt = false`, so a
plain curl works. A GitHub Actions cron (`.github/workflows/keepalive.yml`) pings prod daily so the free project
never pauses during review.

## 8. Client library (`apps/mobile/src/lib`)
- `supabase.ts`: createClient(url, anonKey, { auth: { storage: localStorage, autoRefreshToken: true,
  persistSession: true, detectSessionInUrl: false } }). The env is `EXPO_PUBLIC_SUPABASE_URL` and
  `EXPO_PUBLIC_SUPABASE_ANON_KEY`: from `apps/mobile/.env.local` in local builds, and from EAS environment variables
  in cloud builds (PLATFORMS.md §6: preview = dev project, production = prod project).
- `api.ts`: `suggestMeals`, `mealPlan`, `appleToken`, `deleteAccount`, `sendReport`, each returning a typed result union
  `{ ok: true, data } | { ok: false, error: 'offline'|'rate_limited'|'server'|'invalid' }`. Never throw to the UI.
- `auth.ts`: `signInApple`, `sendEmailCode`, `verifyEmailCode`, `signOut`, `onAuthChange`.
